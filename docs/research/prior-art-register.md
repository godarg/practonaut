## Method and evidence limits

- Sources were read with a fetch tool that returns a **model-generated digest** of the page. Quotes below are what that digest returned as verbatim; they were not character-checked against the raw page except where the entry says so. Version numbers, dates and licenses for GitHub repos were taken from `api.github.com` (repo, releases, tags), because HTML release pages have produced wrong dates in earlier research.
- Tier: **T1** = official docs/spec/source/maintainer; **T2** = peer-reviewed or preprint paper, established analysis; **T3** = vendor marketing, community, third-party summary. Vendor claims stay vendor claims.
- "Does NOT support" lists claims the source should not be cited for. Nothing here says Practonaut is unique or state of the art.
- Historical inputs S01–S05 and S18 (an earlier private research dossier) were re-checked, not copied. Entries that change or sharpen that dossier: P007 (S18), P010 (renderer move, new), P011–P012 (S01), P019 (S02, full text now read), P034 (S04, no licence), P035 (S05, preview, agent-only), P046 (S03).

## Synthesis

**(a) What already exists (in reviewed sources).** Demonstration → deterministic program with independent effect verification, without an LLM in the run loop (OpenAdapt, P011–P012). Demonstration → static image-text tutorials for humans and agents (Demo2Tutorial, P019). Program synthesis from examples/demonstrations with ranking and clarifying queries (FlashFill/PROSE, WebRobot; P020–P022) and mature active automata learning (L*/LearnLib, P023–P024). Executable agent environments with state-based checkers (OSWorld, WebArena, AppWorld, τ-bench, BrowserGym; P026–P033) and generated synthetic agent worlds with verifiers behind MCP or an API (Agent World Model, Patronus DWM; P034–P035). Human practice tools exist per domain: simulated git (Learn Git Branching), real git in a game (Oh My Git!), authored branching scenarios (H5P), real-repo exercises checked by CI (GitHub Skills), editable screencasts (Scrimba), and element-anchored tours (Shepherd, Intro.js).

**(b) Combination not found in reviewed sources.** No reviewed source describes one pipeline that turns an expert's demonstration in a real application into a versioned, provenance- and rights-annotated practice world, runs it deterministically without an LLM, serves a human player and an agent API on the same semantic state, keeps unconfirmed behaviour explicitly "unknown", and grades held-out tasks on the real exported artifact with a transfer step back into the real tool. Closest neighbours each cover a part: OpenAdapt (demo → deterministic run + independent check, aimed at automation), Demo2Tutorial (demo → human/agent learning material, static), AWM/Patronus (generated worlds, agent-only). This is a statement about the 56 sources above, not a global novelty claim.

**(c) Five biggest technical risks and unknowns for the Penpot pilot.**
1. **Observation fidelity.** The Plugin API exposes coarse events (`selectionchange`, `pagechange`, `shapechange` per shape id, `contentsave`) and no documented operation log (P003); Penpot is moving rendering to a WASM/Skia canvas (P009–P010), which removes the DOM/a11y path that rrweb, Playwright and CDP rely on (P013–P018). Whether intent-level operations can be reconstructed from state diffs is unknown.
2. **Rule induction effort.** PBD/PBE works inside a designed DSL with ranking and clarifying queries (P020–P022); L*-style learning needs membership and equivalence oracles (P023–P024). With a human expert as oracle, the number of clarifying demonstrations per confirmed rule is unknown and could dominate cost.
3. **Checker validity and leakage.** Published audits found broken or hackable evaluators at scale: about 10% serious task errors in OSWorld per Epoch (P028), 300+ fixes for OSWorld-Verified (P027), empty responses scored as success in τ-bench (P036), and 9 of 10 benchmarks near-fully hackable in BenchJack (P037). A Practonaut checker that shares state with the agent API inherits classes V1, V2, V4 and V7.
4. **Version drift between world and real tool.** Penpot shipped five releases in ten weeks (P001); the file format carries separate format and data versions plus feature flags (P007); the RPC API is described as "internal" with no stability statement (P006). World packages that are not pinned to an app version will silently diverge, and transfer tests will fail for reasons unrelated to learning.
5. **No single portable sandbox.** Node's permission model is a "seat belt" and does not restrict network in v22 (P054); Docker isolation is incomplete by default (P053); `sandbox-exec` is deprecated (P055); Deno's `--allow-run`/`--allow-ffi` escape (P055); WebContainers need a commercial licence for for-profit production use and are Chromium-first (P052). Running third-party world packages or agent code safely across platforms is unresolved.

**(d) Concrete architecture consequences.**
- **MCP version.** Target MCP **2026-07-28** (modern, stateless, no `initialize`, no sessions, no server-initiated requests) with the TypeScript SDK v2 (`@modelcontextprotocol/server` 2.3.0, Apache-2.0, Node ≥ 20; P039–P042). Ship stdio first. Any HTTP binding binds to 127.0.0.1, validates `Origin` (403 on mismatch) and requires auth (P040). Keep the agent API a transport-independent domain API with MCP as one binding. Do not build on Penpot's own MCP server as a dependency: it uses SDK `^1.29.0` and an SSE endpoint (P004), and modern client ↔ legacy server "Fails" (P041).
- **Recorder approach.** Use a Penpot plugin (`content:read`, events plus shape-tree reads after `contentsave`) together with before/after diffs of exported `.penpot` v3 archives as the ground truth (P002, P003, P007). Screen video is human context only. Do not rely on rrweb, the DOM or the accessibility tree for canvas content. Treat backend RPC and access tokens as an unstable internal path (P006). Pin the Penpot version per world package and record the format, data version and feature flags.
- **Sandbox and delivery boundaries.** Make the deterministic runtime pure TS/Wasm, with world packages as data (no executable code) so that no sandbox is needed for content. Ship it as a static web app with a Service Worker for offline use (secure context, P055). Avoid WebContainers (licence, P052). Use Node `--permission` only as a seat belt for local tooling (P054). Run the result checker out of process, isolated from the agent API, on the exported artifact. Never ship hidden-task answers inside the package (BenchJack V2). Use the ABC checklist and the BenchJack classes as a pre-release audit (P036–P037).
- **Authoring LLM (optional, local).** Use Ollama or llama.cpp only to propose rule hypotheses as JSON-schema-constrained output, with flat schemas that avoid the llama.cpp unsupported features (P056–P057). Every proposal stays "unknown" until an expert confirms it.
