# PADR-0015 — Guided process-repair authoring and durable local projects

Status: accepted · Date: 2026-10-04

## Context and evidence

`measured`: recovery starts at 52fca02fdfc07cd2708939879b1849dbbf378c86, identical
to phase-3-done. The maintainer began a personal recorder/analysis attempt and abandoned it:
purpose, actions and results were incomprehensible. This is one observed attempt, not a

practice transition; task authoring requires JSON/solutions/checker fixtures; a shared question

will value the additional evidence and authoring work. Demand, revenue and competence transfer

## Alternatives and decision

1. Guided, bounded author builder with immediate exercise preview: chosen. It makes the
   existing evidence logic usable and tests the complete product promise.
2. Prepared exercise first: also available as an honestly labelled example, but does not replace
   creation from fresh demonstrations.
3. General demonstration compiler or another adapter: deferred. Closed template matching does
   not support the general promise, and switching tools would not resolve the demonstrated barrier.

Primary user: a trainer or team owner creating a reusable diagram-maintenance exercise.
Pilot: remove the middle step of A → B → C, connect A directly to C and leave exactly one
attached arrow. Three behavioural families are needed: delete_step, reconnect_end and disconnect.
Every executable rule must still have valid proposal and new confirming evidence.

Prepared scene, suggested task, finite variants, witness action recipes and independently
specified example end states are identified as prepared content. Author selection and review
define task intent; they never confirm behaviour. Example expected states are built independently
of the transition engine and compiler; compilation still executes witnesses and invokes the
independent checker. Two valid results retain different arrows; the near miss leaves a loose arrow.

## Contracts and boundaries

- Add optional `repair` task intent to local author/1 projects; legacy projects remain valid.
  No world/package major change. Repair intent, solutions and checker examples never enter practice.
- New bounded authenticated prepare/configure/save/open/launch routes use existing
  revision, Host, Origin, token, JSON and reply guards.
- Named projects persist in a private local host store. Opening revalidates source recordings
  and evidence; stored status strings do not grant authority. Atomic writes, quotas, ownership,
  no-follow checks and a lock protect the new route. Browser storage is not the durable authority.
- Launch starts an owned loopback practice host from the validated compiled world only.
  It never loads the checker bundle; the same required real mirror remains active.
- Normalize inactive bindings of deleted arrows for authoring template comparison only, matching
  the existing editor input semantics. Preserve raw events, full replay and source digests.
  Live bindings and all other semantic fields retain complete equality. Native deletion must be
  freshly evidenced; no hand-written reference rule is borrowed.
- Observation and confirmation are separate states. A refuted alternative has no duplicate
  demonstration request. IDs, indices, raw JSON and provider diagnostics are reachable details.
- No provider, new adapter, MCP, release, download or remote recording transfer.

## Expectations and reassessment

Before the next human sighting, a fresh agent reviewer should explain purpose, first action and
end product in about 30 seconds and complete the small author-to-practice path in about 5–10
minutes using only in-app help. These are provisional design goals, not validated thresholds.
No JSON or internal evidence address is required. Saved work must survive a host restart and
port change. Both valid repair strategies pass; loose/extra arrows and unchanged starts fail.

After two bounded design/operation iterations without a complete explainable path, reassess
user, pilot or scope. Stop immediately on invariant violations. Human VoiceOver/200% zoom
remain OPEN; C6 stays UNKNOWN. Phase 4 is explicitly reconsidered after recovery, never started
because technical tests pass.
